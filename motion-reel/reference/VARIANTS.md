# Hook variants and topic sessions


Each topic produces as many videos as hooks were filmed: one project per hook, same body and CTA, animated once and identical in all of them; only the hook and what depends on it (cover headline, caption if needed) change. **Only the hook-1 project is animated and drafted** (user, 2026-10-29: "necesito solamente ver un borrador, el resto se replica igual"). The other hook projects are prepared and joined but get no plan, animation or draft of their own; once the user approves the hook-1 draft, copy its approved animation and audio into each of them with every time shifted by the difference in hook length (scenes over the hook itself adapt to that hook's words), then render them. Never draft every hook. Before the finals, send the user only the opening of each other hook (from its first frame to about 1 s into the body, captions and animation included) in one message, and wait for their OK on those openings; a fix there only touches that hook's opening. When the host can start separate sessions, start one per topic. Otherwise run topics one after another in this session. Each brief carries: the topic, its approved resource URL (the session sets it in config at init and does not search again), the renamed takes per part (SDR copies from `<batch>/sdr/` when converted), the hooks missing, the notes from L2 for that topic, the script text for the topic, and the rule above. Topic sessions run in direct-to-draft mode (SKILL.md Branch B): the user's first look at each topic is its subtitled, animated draft; from there every gate is theirs.

The session that ran the batch stays light afterwards: it relays decisions that apply to every topic (a short message to each session) and does not read topic transcripts unless asked. Creative approvals (cuts, cover, animation) happen in each topic's session, where the images are.
